# تقرير PDF Documents (PHASE 47 — Document Engine)

## ما تم بناؤه

### توليد PDF حقيقي فالباك اند (مو مكتبة تصوير شاشة)
`pdfkit` — مكتبة Node.js بترسم الـ PDF مباشرة (نص، خطوط، جداول) بدون الحاجة لمتصفح headless (تفادينا Puppeteer عمداً لأنه يحتاج تحميل Chromium من دومين خارج القائمة البيضاء ديال الشبكة).

### مستندان احترافيان
- **Facture (فاتورة العميل)**: رأسية بشعار النظام، معلومات الشركة (ICE)، بيانات العميل، جدول المنتجات (مرجع/اسم/كمية/سعر/إجمالي)، المبلغ المدفوع والمتبقي، حالة الفاتورة.
- **Bon de Commande (طلب الشراء)**: نفس البنية الاحترافية، بيانات المورد بدل العميل، وتكاليف الشراء بدل البيع.
- **محرك تخطيط مشترك** (`renderDocument`) يضمن أن كل مستند صادر عن النظام بنفس الهوية البصرية (نفس الألوان، نفس بنية الجدول، نفس الفوتر) — بدل تكرار الكود لكل نوع مستند.

### API
```
GET /api/documents/invoices/:id/pdf          [finance.view]
GET /api/documents/purchase-orders/:id/pdf   [purchases.view]
```
الاستجابة PDF حقيقي (`Content-Type: application/pdf`) بـ`Content-Disposition: attachment` — يفتح كتحميل مباشر فالمتصفح.

### Frontend
- زر "تحميل PDF" فصفحة `/finance` (لفواتير العملاء).
- زر "تحميل Bon de Commande (PDF)" فصفحة `/purchases`.
- دالة `downloadPdf()` جديدة فـ`api-client.ts`: تجيب الملف بالـ Authorization header الصحيح (الـ PDF مو endpoint عادي JSON)، وتفعّل تحميل حقيقي فالمتصفح (`Blob` → `<a download>`).

```
Backend:  npx tsc --noEmit → صفر أخطاء
Frontend: npx jest        → 17/17 لسا ناجحة (ماتأثرش)
Frontend: npx next build  → ✓ Compiled, 13 صفحة (زادت من 11)، صفر أخطاء TypeScript
```

تفصيل اختبارات `documents.service.spec.ts`:
- **تحقق حقيقي من صحة الـ PDF**: قراءة أول 5 بايتات (`%PDF-`) وآخر 8 بايتات (`%%EOF`) من الـ Buffer المولّد فعلياً — مو افتراض، فحص بنيوي حقيقي لملف PDF صالح.
- **Tenant isolation**: رفض توليد مستند لفاتورة/طلب شراء من شركة أخرى.
- **اكتمال البيانات**: التحقق أن الاستعلام يجيب تفاصيل الأسطر (منتجات) وليس غير رأس المستند.

## القيود
- **اللغة**: المستندات بالفرنسية (اصطلاح شائع فالوثائق التجارية المغربية) — العربية RTL معقدة التنفيذ بـ`pdfkit` (يحتاج محرك تشكيل عربي/bidi غير متوفر بشكل جاهز فالمكتبة). يمكن إضافته لاحقاً بمكتبة متخصصة إذا لزم.
- **لا شعار فعلي (Logo)**: حالياً غير نص "INDUSTRIAL OS" بستايل مطابق للنظام — رفع شعار الشركة (صورة) ممكن يُضاف لاحقاً.
- **فاتورة المورد (Bill)**: لسا ماعندهاش PDF مخصص (بنينا فقط Invoice وPurchase Order) — نفس المحرك يقدر يتوسع بسهولة لها.
- **Templates غير قابلة للتخصيص** من طرف المستخدم (PHASE 47 الأصلية كانت تطلب "Templates قابلة للتخصيص") — حالياً template واحد ثابت لكل نوع مستند.
