# تقرير MFA — التحقق بخطوتين الحقيقي (TOTP)

## ما تم بناؤه

### بروتوكول TOTP معياري (متوافق مع Google Authenticator / Authy)
- `otplib` (النسخة الكلاسيكية `authenticator`) — نفس الخوارزمية المعيارية RFC 6238 المستعملة فكل تطبيقات المصادقة الشائعة.
- توليد QR Code حقيقي (`qrcode` npm) — المستخدم يمسحو مباشرة، بلا إدخال يدوي (مع خيار الإدخال اليدوي للرمز السري إذا تعذّر المسح).

### دورة الإعداد (لا تفعيل تلقائي)
1. `setupMfa()`: يولّد سر TOTP جديد ويخزنو كـ"معلّق" (`mfaEnabled` يبقى `false`) — الحساب **ماشي محمي بعد** لحد التأكيد.
2. `enableMfa(code)`: المستخدم كيدخل رمز حقيقي من التطبيق للتأكيد أنه سجّل السر بنجاح — فقط عندها `mfaEnabled` يتحول لـ`true`.

### دورة تسجيل الدخول (خطوتين حقيقيتين)
- `login()` الآن: إذا الحساب `mfaEnabled`، **لا يصدر جلسة كاملة أبداً** من كلمة المرور وحدها — يرجع **توكن تحدي قصير الأجل (5 دقائق)** بدل الجلسة.
- توكن التحدي محمول بـ claim مميز (`mfaChallenge: true`) — و`JwtAuthGuard` **يرفضو صراحة** إذا حاول أي حد يستعملو كـtoken دخول عادي (دفاع بعمق، مو اعتماد فقط على غياب الصلاحيات).
- `verifyMfaLogin()`: يتحقق من رمز TOTP الحقيقي ضد السر المخزّن، وفقط عندها يصدر الجلسة الكاملة (access + refresh tokens).

### تعطيل MFA — عاملين إلزاميين، ماشي واحد
`disableMfa()` كيرفض التعطيل إلا بـ**كلمة المرور الحالية والرمز الصحيح معاً** — لو حد سرق كلمة المرور وحدها، ما يقدرش يعطّل الحماية.

### API
```
POST /api/auth/mfa/setup          [authenticated]
POST /api/auth/mfa/enable         [authenticated]
POST /api/auth/mfa/disable        [authenticated]
POST /api/auth/mfa/verify-login   [public — يحتاج توكن تحدي صالح]
```

### Frontend
- **صفحة تسجيل الدخول**: خطوة ثانية تلقائية إذا الباك اند رجّع `mfaRequired` — حقل إدخال 6 أرقام بستايل واضح.
- **`/settings` → تبويب "الأمان" جديد**: عرض QR code حقيقي، تأكيد بكود، وتعطيل بعاملين.


**مهم**: الاختبارات ماشي مموّهة (mocked) على مستوى خوارزمية TOTP — كتستعمل `otplib` الحقيقي لتوليد أسرار وأكواد صحيحة فعلياً، والتحقق يوقع على نفس المنطق اللي غادي يخدم فالإنتاج:
- توليد جلسة كاملة **فقط** برمز صحيح حقيقي (مُختبر بكود مولّد فعلياً من نفس السر)
- رفض رمز خاطئ/مزوّر (`000000`) حتى لو التوكن صحيح
- رفض توكن تحدي منتهي أو متلاعب بيه
- رفض استعمال access token عادي كتوكن تحدي (والعكس)
- رفض تعطيل MFA بعامل واحد فقط (كلمة مرور صحيحة بلا كود، أو كود صحيح بلا كلمة مرور)

## القيود
- **السر مخزّن كنص عادي فقاعدة البيانات** (`mfaSecret` عمود String) — فبيئة إنتاج حقيقية، يُفضَّل تشفيره بمفتاح خارجي (KMS) قبل التخزين. موثّق كتحسين مستقبلي.
- **لا رموز احتياطية (Backup/Recovery Codes)** — إذا المستخدم خسر جهازو، ماكاينش طريقة بديلة للدخول غير عبر تدخل الأدمن يدوياً (تعطيل MFA من قاعدة البيانات مباشرة). ميزة الرموز الاحتياطية شائعة فأنظمة مشابهة، مؤجلة.
- **لا فرض MFA إجباري على مستوى الشركة** (مثلاً "كل مستخدم لازم يفعّل MFA خلال 7 أيام") — التفعيل اختياري بالكامل لكل مستخدم لوحده حالياً.
