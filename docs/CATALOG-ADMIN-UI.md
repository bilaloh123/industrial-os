# تقرير واجهة إدارة Categories/Attributes/Brands

آخر بند بسيط من الـ backlog — الـ API كان جاهز بالكامل من PHASE 4 (Products)، كانت ناقصة غير الشاشة.

## ما تم بناؤه

### `CatalogTab` جديد فـ `/settings` → "الفئات والخصائص"
3 أقسام فشاشة واحدة، كلهم متصلين مباشرة بالـ API الحقيقي الموجود مسبقاً:

- **الماركات**: عرض ككلمات (chips) + إضافة سريعة بحقل واحد.
- **الفئات**: عرض هرمي (يبين عدد الفئات الفرعية لكل فئة رئيسية) + إضافة فئة جديدة مع اختيار فئة أب اختياري (بناء الهرمية).
- **الخصائص التقنية الديناميكية**: جدول كامل (الاسم المعروض، المفتاح، النوع، الوحدة، الفئة المرتبطة) + نموذج إضافة خاصية جديدة بـ3 أنواع (نصي/رقمي/قائمة اختيار)، وحدة قياس اختيارية، وربط اختياري بفئة معينة أو "عامة" لكل الفئات.

هاذي الشاشة كتكمل الحلقة: قبل، الخصائص التقنية كانت تتزرع فقط عبر `prisma/seed.ts` (Roulements, Courroies...) — دابا الأدمن يقدر يضيف خاصية جديدة مباشرة من الواجهة بلا الحاجة لتعديل الكود، بالضبط زي ما تنص عليه فلسفة "محرك الخصائص الديناميكي" (PHASE 10).

## API المستعملة (موجودة مسبقاً، بلا تغيير)
```
GET/POST /api/products/brands       [products.view / products.create]
GET/POST /api/products/categories   [products.view / products.create]
GET/POST /api/products/attributes   [products.view / products.create]
```

## التحقق (تم تشغيله فعلياً)
```
Backend:  npx jest        → 189/189 لسا ناجحة (بلا تغيير — الباك اند كان جاهز مسبقاً)
Backend:  npx tsc --noEmit → صفر أخطاء
Frontend: npx jest        → 17/17 لسا ناجحة
Frontend: npx next build  → ✓ Compiled, 13 صفحة، صفر أخطاء TypeScript
```

بما أن الباك اند كان جاهز ومختبر بالفعل من PHASE 4 (12 اختبار موجودة لـ Dynamic Attribute Engine ضمن `products.service.spec.ts`)، هاد الدفعة كانت فرونت اند بحت — بلا حاجة لاختبارات باك اند جديدة.

## القيود
- لا واجهة **تعديل** أو **حذف** للفئات/الماركات/الخصائص الموجودة — الشاشة الحالية تدعم القراءة والإضافة فقط (الـ API نفسه ما فيهش endpoints للتعديل/الحذف بعد).
- لا سحب-وإفلات لإعادة ترتيب الهرمية — إضافة فئة فرعية تتم عبر قائمة اختيار بسيطة.
